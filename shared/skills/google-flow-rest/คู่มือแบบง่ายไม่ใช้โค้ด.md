# คู่มือ Google Flow REST แบบง่ายสำหรับ Codex และ Claude Code

คู่มือนี้ออกแบบให้สมาชิกทีมสั่ง Codex หรือ Claude Code ด้วยภาษาปกติแบบเดียวกับการคุยกับผู้ช่วย ไม่ต้องเปิด Terminal และไม่ต้องพิมพ์คำสั่ง Python

สิ่งที่ผู้ใช้ต้องทำเองมีเพียง:

1. สมัคร useapi.net และรับ API token
2. ล็อกอิน Google และยืนยันตัวตนด้วยตนเอง
3. ใส่ token กับอีเมลลงไฟล์ `.env` ที่ผู้ช่วยเตรียมและเปิดให้
4. ยืนยันก่อนงานที่มีการหักเครดิต

ห้ามส่ง token, cookies, รหัสผ่าน หรือรหัสยืนยันให้ Codex หรือ Claude ผ่านข้อความแชต

## ขั้นที่ 1 — ให้ Codex หรือ Claude Code ติดตั้งสกิล

ส่งไฟล์ `google-flow-rest.zip` ให้สมาชิกทีม แล้วให้เขาแนบไฟล์กับผู้ช่วยหรือบอกตำแหน่งไฟล์ในเครื่อง จากนั้นเลือกข้อความให้ตรงกับโปรแกรมที่ใช้

### ติดตั้งด้วย Codex

> ช่วยติดตั้งสกิล Google Flow REST จากไฟล์ ZIP นี้ให้ผม แล้วแจ้งเมื่อผมต้อง Restart Codex

Codex จะจัดการแตกไฟล์และติดตั้งให้ เมื่อ Codex แจ้งว่าเสร็จแล้ว ให้ปิดและเปิด Codex ใหม่หนึ่งครั้ง

### ติดตั้งด้วย Claude Code

พิมพ์กับ Claude Code:

> ช่วยติดตั้ง Agent Skill Google Flow REST จากไฟล์ ZIP นี้เป็น Personal Skill ที่ `~/.claude/skills/google-flow-rest` ตรวจว่า `SKILL.md` อยู่ถูกตำแหน่ง และแจ้งถ้าผมต้อง Restart Claude Code

หากต้องการให้ใช้เฉพาะโปรเจกต์ปัจจุบัน พิมพ์แทนว่า:

> ช่วยติดตั้ง Agent Skill Google Flow REST จากไฟล์ ZIP นี้เฉพาะโปรเจกต์ปัจจุบันที่ `.claude/skills/google-flow-rest` และตรวจว่า `SKILL.md` อยู่ถูกตำแหน่ง

Claude Code รองรับ Agent Skills โดยตรงและเรียกสกิลได้อัตโนมัติเมื่อคำขอตรงกับคำอธิบาย หรือเรียกตรงด้วย `/google-flow-rest` หากเพิ่งสร้างโฟลเดอร์ skills ระดับบนสุดระหว่างเปิดโปรแกรม อาจต้อง Restart Claude Code หนึ่งครั้ง

## ขั้นที่ 2 — ให้ผู้ช่วยพาเชื่อมบัญชี

หลังติดตั้งแล้ว พิมพ์กับ Codex หรือ Claude Code:

> ใช้สกิล google-flow-rest พาผมสมัครและเชื่อมบัญชี Google Flow กับ useapi.net แบบทีละขั้น

ผู้ช่วยจะเปิดหน้าที่เกี่ยวข้องและนำทางให้ เมื่อพบหน้าล็อกอิน รหัสผ่าน หรือการยืนยันสองขั้นตอน ผู้ใช้ต้องกรอกเอง

แนะนำให้ใช้บัญชี Google แยกสำหรับงานนี้ ไม่ควรใช้บัญชีหลักส่วนตัว เพราะ useapi.net เป็นบริการภายนอกที่ดูแล session ของ Google Flow

## ขั้นที่ 3 — ให้ผู้ช่วยเตรียมไฟล์ .env

พิมพ์:

> ช่วยสร้างไฟล์ .env สำหรับ Google Flow REST ในโฟลเดอร์งานนี้ แล้วเปิดไฟล์ให้ผมใส่ข้อมูลเอง

ผู้ช่วยจะสร้างและเปิดไฟล์ที่มีช่องประมาณนี้:

```dotenv
USEAPI_TOKEN=
GOOGLE_FLOW_EMAIL=
```

ผู้ใช้ใส่ API token หลังเครื่องหมายเท่ากับบรรทัดแรก และใส่อีเมล Google Flow ในบรรทัดที่สอง จากนั้น Save ไฟล์

อย่าส่งเนื้อหาในไฟล์ `.env` ลงแชต อย่าแนบไฟล์นี้ให้ผู้อื่น และอย่าใส่ไว้ใน Git

## ขั้นที่ 4 — ตรวจว่าพร้อมใช้งาน

พิมพ์:

> ตรวจการเชื่อมต่อ Google Flow ให้หน่อย ยังไม่ต้องสร้างวิดีโอและห้ามหักเครดิต

ผู้ช่วยจะตรวจบัญชีและแจ้งว่าพร้อมหรือไม่ หาก session หมดอายุ ให้พิมพ์:

> พาผมเชื่อมบัญชี Google Flow ใหม่

## ขั้นที่ 5 — สั่งสร้างวิดีโอแบบธรรมดา

ตัวอย่างคำสั่ง:

> ช่วยเตรียมวิดีโอผู้หญิงวิ่งเล่นในสวนยามเย็น แนวตั้ง 720P 10 วินาที แต่ขอดูรายละเอียดก่อน ยังไม่ต้องส่งสร้าง

ผู้ช่วยจะสรุปโมเดล ความละเอียด ระยะเวลา จำนวนคลิป และภาพอ้างอิง โดยยังไม่หักเครดิต

เมื่อตรวจถูกต้องแล้ว พิมพ์:

> ยืนยัน ส่งสร้างตามรายละเอียดนี้ได้เลย

ผู้ช่วยจึงจะส่งงาน รอผล ดาวน์โหลด และตรวจไฟล์ให้

## ขั้นที่ 6 — สร้างจากภาพอ้างอิง

แนบภาพหรือบอกตำแหน่งไฟล์ แล้วพิมพ์:

> ใช้ภาพนี้เป็นตัวละคร ทำวิดีโอแนวตั้ง 720P 10 วินาที ให้เธอเดินในร้านอย่างเป็นธรรมชาติ มีเสียงบรรยากาศ ไม่มีดนตรี ขอดูรายละเอียดก่อนส่ง

หากมีหลายภาพ:

> ภาพที่ 1 คือตัวละคร ภาพที่ 2 คือสถานที่ ล็อกหน้าตา เสื้อผ้า และฉากตามภาพ แล้วเตรียมวิดีโอให้ผมตรวจ

ผู้ช่วยจะจับคู่ภาพกับบทบาทให้ ก่อนส่งจริงควรตรวจว่าตัวละครและสถานที่ถูกต้อง

## ขั้นที่ 7 — ส่งหลายคลิปหรือทั้งเรื่อง

แนบไฟล์เนื้อเรื่องหรือ Shot Breakdown แล้วพิมพ์:

> อ่านไฟล์นี้ แบ่งเป็นคลิปตามแต่ละช็อต เตรียมรายการโมเดล ความละเอียด ระยะเวลา และจำนวนงานทั้งหมดให้ผมตรวจก่อน ห้ามส่งสร้างจนกว่าผมจะยืนยัน

หลังตรวจรายการแล้ว พิมพ์:

> ยืนยันรายการนี้ ส่งทั้งหมดได้เลย ดาวน์โหลดและตรวจทุกไฟล์ให้ด้วย

ผู้ช่วยจะสร้างไฟล์รายการงาน จัดการส่งแบบ batch บันทึก Job ID ป้องกันการส่งซ้ำ รอผล และรายงานช็อตที่สำเร็จหรือล้มเหลว

## ขั้นที่ 8 — ตรวจสถานะงานเดิม

พิมพ์ได้โดยไม่ต้องจำ Job ID:

> ตรวจงาน Google Flow ชุดล่าสุดให้หน่อย งานไหนเสร็จแล้วให้ดาวน์โหลดและตรวจไฟล์

หรือ:

> งานที่ยัง processing อยู่เสร็จหรือยัง

ผู้ช่วยจะอ่าน Job ID จากไฟล์สถานะของโปรเจกต์

## ขั้นที่ 9 — เมื่องานล้มเหลว

พิมพ์:

> ช่วยตรวจสาเหตุของงานที่ล้มเหลว แต่อย่าเพิ่งส่งซ้ำ

ผู้ช่วยจะรายงานสาเหตุก่อน การส่งซ้ำอาจเสียเครดิตเพิ่ม จึงต้องยืนยันใหม่ เช่น:

> ยืนยันให้ลองส่งซ้ำเฉพาะ Shot 05 หนึ่งครั้ง

## ตัวอย่างข้อความที่ใช้บ่อย

### ตรวจบัญชี

> ตรวจบัญชี Google Flow ที่เชื่อมอยู่ให้ผม แต่ห้ามสร้างงาน

### ทดลองหนึ่งคลิป

> เตรียมทดลองหนึ่งคลิป แนวตั้ง 720P 10 วินาที ใช้ภาพนี้เป็นตัวละคร ขอ Dry-run ก่อน

### งานมีบทพูด

> ทำวิดีโอตามช็อตนี้พร้อมเสียงพูดภาษาไทยตรงตามบท มีเฉพาะเสียงพูดกับเสียงในฉาก ไม่มีดนตรี

### ส่งทั้งชุด

> สรุปจำนวนคลิปและสเปกทั้งหมดให้ผมตรวจ ถ้าผมตอบว่า “ส่งเลย” จึงค่อยส่งจริง

### ดาวน์โหลดและตรวจ

> รอจนงานเสร็จ ดาวน์โหลดทั้งหมด แล้วตรวจความยาว ความละเอียด codec และเสียง

## สิ่งที่ผู้ช่วยควรรายงาน

- ใช้บัญชีใดและ session พร้อมหรือไม่
- จำนวนคลิปที่จะส่ง
- โมเดล ความละเอียด แนวภาพ และระยะเวลา
- งานใดส่งสำเร็จหรือถูกปฏิเสธ
- งานใดยังประมวลผล
- ตำแหน่งไฟล์ดาวน์โหลด
- ความยาว ความละเอียด codec และเสียงของไฟล์จริง

## ข้อจำกัดที่ผู้ใช้ควรรู้

- useapi.net ไม่ใช่ Google API อย่างเป็นทางการ
- ราคา รุ่นโมเดล และข้อจำกัดอาจเปลี่ยนได้
- การสมัคร การชำระเงิน การล็อกอิน Google และรหัสยืนยันต้องทำด้วยตนเอง
- ผู้ช่วยไม่ควรส่งงานเสียเครดิตจนกว่าผู้ใช้จะเห็นรายละเอียดและยืนยัน
- คำว่า `processing` ยังไม่ถือว่าได้รับวิดีโอ
- งานล้มเหลวไม่ควรถูกส่งซ้ำอัตโนมัติ

สำหรับสมาชิกทีมทั่วไป ให้ใช้คู่มือฉบับนี้เป็นหลัก ส่วนคู่มือฉบับเต็มใช้เฉพาะเวลาต้องแก้ปัญหาทางเทคนิค
